# Erreurs & pièges connus — cloudflare-monetization

Journal court des bugs/pièges Wrangler/Cloudflare rencontrés et leur fix, un par ligne, le plus récent en haut. Ne duplique pas le statut projet (→ `EXECUTIVE_SUMMARY.md`).

- 2e binding `analytics_engine_datasets` sur un Worker existant → `writeDataPoint()` bloque indéfiniment (cause plateforme inconnue, reproduit 2x `wrangler dev --remote`, `tsc`/`vitest` ne détectent rien). Fix : réutiliser le dataset existant avec un discriminant plutôt qu'un 2e dataset dédié.
- `wrangler secret put` redéploie "la dernière version" et refuse après un rollback actif → utiliser `wrangler versions secret put` pour modifier un secret sans redéployer.
- `workers_get_worker_code` renvoie toujours la dernière version uploadée, pas forcément celle qui sert le trafic live après un rollback → croiser avec un test HTTP réel ou `wrangler deployments list`.
- API SQL Analytics Engine rejette `\` et `'` dans les chaînes (422) → formuler les `LIKE` sans backslash.
- Dashboard "Quick Edit" sur un Worker connecté à Workers Builds est écrasé silencieusement au prochain `git push` → toujours committer le fix dans le repo, jamais de patch (Sphere ou autre) en Quick Edit direct.
- Un annuaire tiers qui sonde l'URL nue (GET sans query/mauvais verbe) conclut à tort à l'absence de support x402 → `/.well-known/x402` (ajouté sur les 3 produits le 08/09) corrige la détection.
- **[CORRIGÉ 2026-09-12]** L'entrée précédente ("facilitator CDP n'émet jamais EXTENSION-RESPONSES") était incomplète — [x402#2112](https://github.com/x402-foundation/x402/issues/2112) a été fermé le 2026-07-16 par un mainteneur CDP comme "not reproducible" : la vraie cause chez la plupart des rapporteurs était `extensions.bazaar.discoverable: true` (champ invalide, casse la découverte), x402 v1 (non supporté par Bazaar), ou `paymentPayload.resource` absent (requis pour la découverte, pas pour le règlement — non documenté à l'époque). Notre implémentation utilise déjà `declareDiscoveryExtension` officiel (@x402/extensions/bazaar) sur les 4 produits, probablement correcte sur ces points. **Le vrai gap chez nous** : le catalogue Bazaar est alimenté spécifiquement par le CDP Facilitator (`api.cdp.coinbase.com/platform/v2/x402`, nécessite des identifiants API CDP) — on utilise `facilitator.payai.network`, jamais celui de CDP, donc probablement hors du catalogue Bazaar quoi qu'on fasse côté code. Le fil de l'issue reste actif jusqu'au 2026-09-09 (d'autres rapportent le même symptôme après la fermeture) donc un doute résiduel demeure sur le sujet. Priorité basse : un vendeur confirmé indexé depuis juillet (`api.wallettriage.com`) rapporte 7 appels/2 mois, 1 seul payeur (lui-même) — "getting indexed gets you found, not bought" (cité par un autre commentateur du fil).
- CPU 10ms/requête n'inclut pas l'attente `fetch()` (I/O exempté) — latence perçue élevée sur un appel externe n'est pas une alarme en soi.
- KV limité à 1000 writes/jour/namespace → JWT stateless par défaut pour l'auth/session, pas d'écriture KV par requête.
- Workers AI 10 000 Neurons/jour est un quota GLOBAL au compte, pas par Worker → à surveiller dès qu'il y a plus d'un produit IA actif.
